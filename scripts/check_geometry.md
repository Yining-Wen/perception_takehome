# 第三步：跨帧三维一致性

```bash
uv run python scripts/check_geometry.py
uv run python scripts/check_geometry.py --scenes scene_c
```

输出位于 `deliverables/geometry_audit/<scene>/`。覆盖全部帧，以间隔 1、5、10 帧的双向重投影检查局部几何；不是全序列所有两两组合，也不是全局回环检测。默认深度像素 stride=8（每隔 8 个像素取一个点），减少 CPU 开销，不抽掉时间帧；可用 `--stride 4` 加密。

## 数据与前两步的关系

使用深度图、深度内参、scale_m、T_color_depth、给定逐帧轨迹、sync.json，以及第二步输出的旋转候选（如果存在）。保留原始配对，不自动接受第一步的重配对候选。

全部帧对输出误差。拟合尺度要求两端 RGB–depth 时间差均不超过 5 ms、平移基线至少 3 cm、正反方向各至少 50 个支持点。两端必须位于同一个 5 秒时间块并避开首尾 0.5 秒；时间块依次分给训练、验证和测试。至少每组 10 对，才拟合尺度。这里的 test 是场景内留出片段，不是题目的 test 场景。

第二步 RGB 主点和焦距候选不会改变深度点云，所以在这里与原始标定完全等价，不重复计算。比较原始外参与旋转候选，可以提供额外证据，但无法直接证明 RGB 内参的正确值。第二步旋转候选已经使用过相应数据，因此此处留出结果是条件性交叉检查，不是完整流水线的全新盲测。

## 计算

将 i 帧深度点变换到 j 帧深度相机：

```text
T_depth_j_depth_i = inv(T_color_depth)
                   @ inv(T_world_camera_j)
                   @ T_world_camera_i
                   @ T_color_depth
```

投影到 j 帧深度图，使用 2×2 有效、局部平滑像素的双线性深度采样。原始标定下，明显位于目标表面后方的点作为遮挡剔除；这形成固定支持集合。所有候选使用相同支持点，出界或失效记 15 cm 惩罚，不能通过丢点提高分数；同时报告保留比例。正反两个方向的截断平均误差取均值，每个帧对同等权重。

深度尺度变小会让以米计的误差自然变小。因此用于拟合的误差统一除以候选尺度倍率，在原始 scale_m 对应单位下比较；CSV 另列候选真实米制的残差中位数。后者不应单独用于选尺度。

分别固定原始外参和第二步旋转候选，在 0.8–1.2 倍范围扫描尺度（默认 0.02 步长）。训练集选择每种外参的尺度，验证集比较模型，测试集复核。范围边界最优、收益不足、支持点损失过多都会阻止通过初筛。验证和测试均要求改善至少 1 mm 且 10%、至少 60% 帧对改善、平均支持保留率至少 80%。这些是诊断阈值，不是部署标准。

## 输出

- `pairs.csv`：全部帧对、时间差、平移基线、数据分组、原始支持数量、各模型误差和支持保留比例。
- `scale_search.csv`：仅训练片段的尺度扫描曲线。
- `summary.json`：尺度结果、验证/测试统计、待复核轨迹帧、限制和参数。
- `calib_candidate_original_scale.json`：原始外参 + 候选深度比例。
- `calib_candidate_rotation_scale.json`：第二步旋转候选 + 候选深度比例（有旋转输入时）。
- `trajectory.csv`：逐帧平移/旋转速度，超过中位数 + 8 倍 robust sigma 的跳变标记。标记不代表轨迹确定错误。
- `geometry.png`：长间隔帧对误差、尺度扫描、轨迹速度曲线。

## 能与不能得出的结论

可以发现局部跨帧不一致、判断候选外参是否改善深度几何，并估计相对于给定轨迹平移尺度的深度比例。原始标定不覆盖，轨迹不自动优化。

不能独立证明真实米制尺度：轨迹尺度错了也会影响拟合结果。不能验证绝对世界原点或朝向。当前版本不优化深度内参、外参平移，不执行 ICP、回环闭合或 surveyed boxes 验证。固定重叠/遮挡集合会造成选择偏差，尤其严重故障可能失去支持；必须同时看支持数量、无评分帧对和跨时间的误差，而非只看均值。动态物体、平面退化、传感器噪声也会影响指标。

如果尺度曲线近乎平坦，即使有一个数值最小点，也不能认为尺度已经被可靠辨识；如果原始和旋转候选均有大残差，应继续检查轨迹、时间配对和其他参数。候选文件只供复核，不代表自动接受。
