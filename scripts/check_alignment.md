# 第二步：RGB–depth 空间对齐检查

```bash
uv run python scripts/check_alignment.py
# 单个场景
uv run python scripts/check_alignment.py --scenes scene_b
```

全量检查四个场景的每一帧，结果在 `deliverables/alignment_audit/<scene>/`。不抽取少数帧代替全量检查；调参、模型选择与最终验证使用不同时间片段。

## 与第一步的关系

保留原始 RGB–depth 配对，不自动采用第一步尚未复核的候选。全部帧输出对齐误差；只有原始配对时间差绝对值不超过 5 ms、深度与 RGB 均有至少 30 个有效边界点的帧参与参数估计和验证。这样避免把已知的大时间错配拟合成空间标定修正。小时间差也不保证真实同步。

按 5 秒划分时间块，每三个块分别用于训练、验证、最终测试，每块首尾各留 0.5 秒隔离区。隔离区和时间不匹配的帧仍计算误差，但标记 `audit_only`。这里的 test 是每个场景内部留出片段，不是题目 dev/test 场景划分。每类至少需要 10 帧，否则只做原始对齐检查。

## 检查和拟合的参数

独立测试三种假设，均从原始标定出发，不串联修正：

| 模型 | 变化参数 | 默认范围 |
|---|---|---|
| principal | RGB `cx, cy` 的加法偏移 | 各 ±20 像素 |
| focal | RGB `fx, fy` 的乘法变化 | 各 exp(±0.12)，约 0.887–1.127 倍 |
| rotation | `T_color_depth` 旋转的左乘修正 | 旋转向量每轴 ±4 度 |

深度内参、深度比例、外参平移、轨迹全部固定。当前检查不能独立验证深度绝对尺度，也不声称完整重标定了整套设备。RGB 内参与相机间旋转互相耦合，多个模型都改善时，不代表同时发现多个独立故障。

## 误差与优化

从有效深度像素之间提取深度跳变的前景侧，忽略无返回边界；用原始标定的 z-buffer 过滤遮挡，保留对应三维点。所有候选使用同一组支持点，投影出图像或到相机后方的点记为 10 px 惩罚，避免通过丢弃难点降低误差。

RGB 使用 Gaussian + Canny；对其边缘距离图双线性采样。每帧指标为截断到 10 px 的边缘距离均值；优化目标是训练帧指标的均值，每帧权重相同。主点与旋转模型先做粗初始化，再做有界 Powell 优化。边界支持集合固定，因此只适合局部候选检查；大变化或复杂遮挡应另外验证。叠加图会重新计算候选可见边界，和固定支持数值指标略有区别。

参数仅由训练片段优化。验证片段选择平均误差最低的模型，最后查看其测试片段结果。只有优化收敛、未逼近搜索边界，且验证和测试均满足以下条件，才标记为值得复核：

- 平均误差减少至少 0.25 px 且至少 10%。
- 至少 60% 的帧改善。

这些是可复现的初筛标准，不是机器人部署验收阈值。没有通过不意味着标定正确；超出搜索范围、多个参数同时错误、弱几何约束等都可能造成失败。纹理、动态物体和深度缺失也会影响结果。

## 输出

- `frames.csv`：每帧时间差、分组、边界数量、各模型误差。无法评分的值为 NaN。
- `summary.json`：三种候选参数、优化器是否收敛、训练/验证/测试统计、模型选择和限制。
- `calib_candidate_principal.json`、`calib_candidate_focal.json`、`calib_candidate_rotation.json`：完整可加载的候选标定。候选可能没有通过复核标准；先看 summary，再决定是否使用。
- `timeline.png`：原始时间差和各模型全量对齐误差。
- `overlay_*.png`：选中模型在测试片段的叠加图，覆盖改善量从差到好的分位点，不只展示成功案例。

原始 calib.json 和 sync.json 不会修改。将候选用于第三步跨帧几何检查后，再决定是否接受。不要直接把验证集排名最低的模型当作真实故障原因。
